# Архитектура транспорта MODX 2

Build: `_build/package.json` → curated source payload/inventory → штатный `modPackageBuilder` → 11 xPDOObjectVehicle → native ZIP → metadata normalization → SHA256/verification. Namespace, семь settings, menu, snippet и chunk представлены нативными vehicles; controller, processors, lexicons и adapters — файловой частью. Permission definitions создаются через xPDO при активации; policy data не обновляется.

Каждый vehicle имеет стабильный GUID/UNIQUE_KEY, `UPDATE_OBJECT=false`, `UNINSTALL_OBJECT=false`, `ABORT_INSTALL_ON_VEHICLE_FAIL=true`. Ключи объектов из установленного сайта не попадают в build. Архив содержит только source defaults; private audit setup выполняется оператором отдельно.

Первый namespace validator проверяет версии, private state path, namespace conflict, права/canonical destinations, известные runtime hashes и InnoDB object tables. Затем начинается DB transaction. Нативный file resolver переносит payload в неактивный component `.stage/<signature>/`; direct HTTP доступ защищён core/component deny rules. Settings/menu/snippet vehicles создают только отсутствующие записи. Menu validator принимает ранее переименованный пункт по namespace/action, сохраняя его естественный PK.

Последний **chunk validator** выполняет активацию под private filesystem lock и сверяет generation ledger. При первом install он сохраняет отсутствующий chunk через xPDO до последнего vehicle lookup; это позволяет завершить весь набор в одной проверяемой границе. Известные stock elements обновляются, изменённые сохраняются с отдельной versioned stock-копией. Payload checksums проверяются при активации; runtime заменяется atomic rename с принудительной invalidation PHP OPcache, оригиналы ручной установки сохраняются приватно. После записи ledger коммитится DB transaction. Native Package Manager самостоятельно обновляет transport package status/cache/events.

Почему validator: в MODX 2.8.8 `_installObject()` возвращает `saved || (exists && !upgrade)` независимо от результата `resolve()`. Один resolver не обеспечивает правдивый статус отказа для preserved object. Validator возвращает false до lookup/save последнего vehicle; `ABORT_INSTALL_ON_VEHICLE_FAIL` передаёт отказ native PM. При ошибке активации восстанавливаются bytes/modes и element rows, удаляются созданные объекты, DB откатывается. Shutdown handler откатывает transaction, если native PM остановился на более раннем vehicle. Неактивная `.stage` может остаться для диагностики; отсутствие transient каталога не является критерием rollback.

Uninstall идёт в обратном native порядке, поэтому chunk validator выполняет safe uninstall первым. Сначала проверяются все необходимые backups, затем удаляются/восстанавливаются только совпадающие по installed hash файлы в пределах component-owned paths. Modified/untracked files сохраняются. Existing namespace/settings/elements/ACL не удаляются. Superseded package не может удалить active generation. Ledger/backups сохраняются для повторной установки и отдельного решения о purge.

Это локальная гарантия на проверенном InnoDB/одном filesystem/одном узле. Multi-node shared storage, аварийное отключение питания, реальный ENOSPC и runtime DB outage не аттестованы. Пакет отказывает на MyISAM/других DB engines; это осознанное ограничение private beta. Нельзя заменять опубликованный ZIP под прежней signature: native extracted package/OPcache могут содержать старую версию metadata. Для нового кода нужна новая signature.

Новый audit config reader отличает environment (trusted PHP/JSON) от setting (JSON only), проверяет private canonical file/no links, ограничивает размер/schema и возвращает наружу только readiness/source. Повреждённый JSON конфигурации — серверный отказ 503; malformed клиентский JSON — 400. Секреты не передаются в public registry, CMP preview, package ledger или ZIP.
