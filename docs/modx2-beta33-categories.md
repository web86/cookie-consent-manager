# beta33 — видимость категорий и пользовательские интеграции

На вкладке «Сервисы» каждая необязательная категория имеет независимый checkbox «Показывать в настройках cookie» и кнопку сворачивания. Сворачивание влияет только на текущую страницу Manager, сохраняется при добавлении/сохранении и не записывает consent-настройки. Ошибка раскрывает раздел. Necessary всегда присутствует.

В `cookie_consent.options` сохраняются три boolean `categories` и три целочисленных `category_versions`. При native upgrade с beta32 флаги однократно вычисляются по включённым сервисам; версии начинают с нуля, поэтому неизменившиеся согласия категорий не сбрасываются. После миграции сервисы не меняют видимость. Новая установка получает все три флага false независимо от реестра: администратор явно включает используемые категории, в том числе для собственных callbacks без зарегистрированного сервиса.

При изменении видимости Save увеличивает версию только затронутой категории под DB lock. Сервер управляет версиями; draft не может их обнулить. Скрытые разрешения не используются. Скрытие и повторное включение требуют нового выбора даже у посетителя, который не заходил на сайт между изменениями. Остальные предпочтения и consent_id сохраняются. Это требует обновлённого HTML: после обновления очищайте штатный кэш MODX и кэш HTML/CDN. Открытые до изменения страницы применят новую конфигурацию после перезагрузки; мгновенного broadcast старым вкладкам нет.

PHP SSR, браузер, preview и per-map flow используют одинаковые флаги. Видимая категория без сервисов допускает `onAllowed(category, callback)`. Вариант `{service:'key'}` дополнительно требует включённого сервиса и точного fingerprint. Скрытая external_content не позволяет загрузить карту кнопкой. При видимой категории штатный явный map_allow сохраняется. Контракт `stillAllowed()`/`unsubscribe()` остаётся прежним; [примеры JS-карт](modx2-beta32-callbacks.md) применяются владельцем отдельно.

## ClientID Метрики вне ядра

Ядро больше не получает ClientID и не записывает `#clientid` для Битрикс24 или других форм. Checkbox удалён из Manager и RU/EN stock-подписей. Старые `clientId: true/false` принимаются только как boolean и удаляются при native миграции/сохранении. Строки, числа, массивы и null отвергаются. Пользовательские переводы не переписываются.

Удаление параметра меняет fingerprint Метрики, в том числе для старого значения по умолчанию. Старый fingerprint не получает alias; согласие на конкретную Метрику нужно подтвердить повторно. Fingerprint остальных сервисов не меняется. Категорийное разрешение для независимых callbacks сохраняется, если видимость не менялась.

Если форма использует ClientID, владелец может создать пользовательский чанк по [YandexMetrikaClientId.html](../examples/chunks/YandexMetrikaClientId.html) и вызвать его после Banner. Пример не устанавливается пакетом, не загружает SDK, не является обязательным для отправки формы. Он использует `onAllowed('analytics', ..., {service:'yandex'})`, ID из проверенного реестра, стандартную очередь `ym` и повторную проверку `stillAllowed()` в асинхронном ответе. При другом ключе экземпляра замените ключ в обоих местах. Сначала проверьте на staging. Реальная отправка данных в Битрикс24 не входит в проверку.

## Обновление

Сделайте резервную копию DB, пользовательских/static исходников пяти canonical элементов, runtime, audit-конфигурации и журналов. Native Package Manager обновляет код CookiesPopup, CookieConsent, CookieConsentAssets, CookieConsentBanner и CookieConsentMap на месте с предупреждением. ID, category, properties и пользовательские метаданные сохраняются. Не создаются stock-копии, plugins или пользовательский CustomScripts. Native uninstall сохраняет DB-настройки, элементы, ACL и журналы; убирайте вызовы из шаблона перед uninstall. Не обещается атомарный rollback при произвольных поздних файловых ошибках: используйте backup/restore.

Старый first-party mock `bitrix24-clientid.js` больше не поставляется и не вызывается. Native upgrade может оставить прежний файл старой версии; он не является работающей интеграцией. Не запускайте uninstall старого пакета поверх новой версии.
