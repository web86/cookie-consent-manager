# Краткая ручная проверка тестовых релизов

- MODX 2: `cookieconsent-1.0.7-beta2.transport.zip`, обновление **1.0.6 → 1.0.7-beta2**.
- MODX 3: `cookieconsent3-0.1.0-beta6.transport.zip`, обновление **beta4 → beta6**.

1. **Сохраните перед обновлением:** backup БД/файлов, текущие настройки и режим
   Strict/Legacy, каталог `services/`, собственные JS, рабочий bundle и его timestamp,
   приватные manifest/checksums, JSONL и audit-конфигурацию. Запишите SHA256 изменённых
   адаптеров и список намеренно удалённых файлов.
2. **Сверьте SHA256 ZIP и платформу.** Загрузите соответствующий архив в стандартный
   Package Manager MODX и установите новую версию поверх старой. **Uninstall не нужен.**
   Не заменяйте bytes уже установленной signature.
3. **После успешной установки** один раз очистите кеш из Manager и перезагрузите
   страницу компонента. Установка/очистка кеша используют PHP-сборщик; Node/npm/Composer
   на сервере клиента не нужны. Проверьте новую версию в интерфейсе.
4. **Сверьте адаптеры:** пользовательские hashes/пути/дополнительные файлы должны
   сохраниться, намеренно удалённые — остаться удалёнными. В приватном
   `adapter-checksums.json` должны быть старый и новый baseline. Обязательный удалённый
   или некорректный input ожидаемо оставляет прежний bundle и статус ошибки; автоматического
   восстановления такого исходника нет.
5. **Проверьте ручную сборку:** «Настройки → Дополнительные настройки → Сборка адаптеров».
   Нажмите «Пересобрать адаптеры», дождитесь ответа, проверьте статус/дату. При ошибке
   прежние bundle и дата успеха должны сохраниться. Custom JS в общую сборку не входит.
6. **Проверьте поведение:** настройки/сервисы/ID/параметры, сохранение закрытой карточки,
   руководство, custom service по умолчанию, RU/EN, журнал/фильтры/пагинацию и CSV с
   «Страница». Новое событие должно содержать только pathname без query/hash. В чистом
   профиле проверьте Strict до/после согласия, reload/revoke, callbacks/карты/видео/iframe;
   отдельно — прежнюю семантику Legacy и реальные SDK/плееры. Reconsent затрагивает всех:
   на основном сайте запускайте его только намеренно, с подтверждением.
7. **При ошибке остановитесь:** сохраните результат Package Manager, signature/SHA256,
   MODX/PHP/версию компонента, время/шаги, статус сборки, HTTP/request_id, PHP error.log и
   JS console/network errors, проблемные пути/hashes/права. Не передавайте пароли, modAuth,
   audit-ключи и полный журнал посетителей. Native failure может оставить частичную
   установку; используйте обычный backup-процесс.

Сторонняя проблема pdoTools3 3.1.0 с warm Fenom cache не исправлялась и не является
ошибкой этих тестовых пакетов. Полные пояснения: `manual-testing.md`.
