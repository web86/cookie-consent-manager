Cookie Consent Manager — native MODX 2 package (beta21)

No Setup Options or package-state directory. Open Extras → Cookie Consent Manager. Log opens a read-only Audit Viewer (requires cookie_consent_view_logs; installation does not grant this permission to Manager users). Filters/search apply with Find, 50-row cursor pages and streamed UTF-8 CSV cover old/new logs. Storage settings are below the table. There choose website-relative storage (e.g. /logs/cookies/) or an absolute private directory, then Check and enable journal. Other form edits use Save, independently of the journal draft. A private directory outside DOCUMENT_ROOT is recommended. The component does not check HTTP access or create/modify journal .htaccess. The site owner is responsible for protecting logs, including through proxy/CDN. Apache, nginx and LiteSpeed use the same filesystem checks. Legacy environment/private JSON configuration remains supported and takes precedence.

CookiesPopup is markup only. CookieConsent renders localized strings/notice HTML and stored TTL/policy/buttons on the server before JavaScript, using context cultureKey and the same CookieConsentTexts resolver as preview. Live mode is default, mock only explicit. Public preferences expose four categories only. Active providers stay internal; newly added/changed services and legacy partial permissions require review and never expand silently.

Managed setup stores origin/rate in cookie_consent.audit and a random HMAC key in the native server-side MODX DB Registry (never system config JS or public registry). Protect DB/backups/core. No .htaccess is shipped or written by this package; protect public core paths in your server configuration. Existing .htaccess files are retained. No secret is generated by installation itself. POST testing adds a real test event; old logs are never removed.

Add [[!CookieConsent]] once to a shared template. Remove old direct analytics scripts and noscript pixels. Use CookieConsentMap separately on map pages with reviewed HTTPS embed URLs. No templates are edited by installation; optional services start disabled. The unified snippet uses live mode by default; mode=mock is only for isolated acceptance tests.

WARNING / ВНИМАНИЕ BEFORE INSTALL: source code of CookiesPopup, CookieConsent, CookieConsentRegistry and CookieConsentMap WILL BE REPLACED. Back up DB/elements and any static source files first. Stable IDs, names, element types, properties and links are retained; static canonical elements become DB-backed and their original files are not edited. No new *_package_VERSION elements are created; existing old copies are not deleted. Settings, all saved translations/notice HTML/service parameters, browser consent and logs are preserved. Native core/packages/SIGNATURE/preserved.php contains pre-install object snapshots but is overwritten by reinstall; protect/copy it or use a DB backup. restore-elements.php supports hash-only preview and explicit in-place restoration for DB-backed snapshots. Ordinary text edits preserve consent; only the confirmed advanced reconsent action changes policy version.

Back up DB (including native registry tables), elements/templates, customized runtime, private legacy config and JSONL before upgrading. Native file vehicles replace package runtime files; direct changes require backup/merge. MODX core/packages native archives help recovery, but partial DB/filesystem errors are not atomic and no custom rollback is promised.

Uninstall removes exact shipped files and retains settings/elements/menu/ACL, native audit key/config, logs and untracked files. Remove template connections first; retained menu/elements can refer to removed code. Full purge is an explicit administrator decision. Do not run superseded ledger-based beta uninstall over a newer installation.

Newly created monthly logs start with # Cookie Consent Manager audit log, then JSON records. Existing logs are never rewritten. This is a header-aware line format, not strict JSONL. All bundled readers accept both forms and diagnose invalid lines. Viewer has no SQL event tables or hidden PII copies; each search/page is a bounded-memory scan. CSV uses source file/line order and excludes diagnosed invalid rows. Protect exported personal data.
