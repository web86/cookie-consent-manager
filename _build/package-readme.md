Cookie Consent Manager — native MODX 2 package (beta26)

No Setup Options or package-state directory. Open Extras → Cookie Consent Manager. Journal settings are at the end of Main and use the single Save button. Fresh installations propose the target host MODX_CORE_PATH + cache/logs/; upgrades keep existing paths, including an intentionally empty disabled value. An empty path stops new events without deleting old logs. Save checks a new/changed existing directory with a temporary local PHP exclusive write/flock/read/cleanup proof, initializes audit configuration and never sends HTTP self-requests or fictitious consents. On journal failure other valid settings are saved and the previous path is retained with an explicit partial result. Unchanged valid paths/configuration are not write-tested again. No directories or .htaccess are created automatically. Back up consent logs, including before manually clearing the entire core/cache directory; ordinary MODX cache clearing preserves logs. Logs use YYYY-MM-cookie-consent.log, separately from error.log.

The Log tab is a read-only Audit Viewer with year/month/action/search, Find, totals/CSV, three columns, details and pagination. It requires cookie_consent_view_logs and remains available without settings permission. No storage configuration or diagnostics panel is displayed there. The site owner controls HTTP protection of log directories, proxies/CDN and public core paths.

CookiesPopup is markup only. CookieConsent renders localized strings/notice HTML and stored TTL/policy/buttons on the server before JavaScript, using context cultureKey and the same CookieConsentTexts resolver as preview. Live mode is default, mock only explicit. Public preferences always show necessary; optional categories appear only when they contain an enabled service, including in server rendering and unsaved Manager preview. Active providers stay internal; newly added/changed services and legacy partial permissions require review and never expand silently.

Managed setup stores origin/rate in cookie_consent.audit and a random HMAC key in the native server-side MODX DB Registry (never system config JS or public registry). Protect DB/backups/core. No .htaccess is shipped or written by this package; protect public core paths in your server configuration. Existing .htaccess files are retained. No secret is generated by installation itself. On initial configuration Save can use the authenticated Manager origin; existing configuration/origin/key/rate are retained. A legacy private configuration is never overwritten. Local readiness does not prove public HTTP delivery. Real browser events still use strict Origin/schema/provider validation, HMAC/replay/rate controls, IP/User-Agent/server time and event_id ACK. Old logs are never removed.

Use [[!CookieConsentAssets]] exactly once in head and [[!CookieConsentBanner]] exactly once before closing body. Alternatively keep legacy [[!CookieConsent]] once; never mix methods or repeat tags. The two fragments are independent and do not suppress repeated PHP output. Static text/notice HTML/ARIA is resolved by PHP with saved overrides; JS only clones minimal dynamic map/reopen templates and reads runtime messages. Public JSON contains no strings collection. Assets use one content-hashed minified CSS and one deferred minified JS. Minification is build-time only. No MODX plugins/global events rewrite pages. Remove old direct analytics scripts and noscript pixels. Use CookieConsentMap separately on map pages with reviewed HTTPS embed URLs. No templates are edited by installation; optional services start disabled. The unified snippet uses live mode by default; mode=mock is only for isolated acceptance tests.

Newly created monthly logs start with # Cookie Consent Manager audit log, then JSON records. Existing logs are never rewritten. This is a header-aware line format, not strict JSONL. CSV uses source file/line order and excludes diagnosed invalid rows. Protect exported personal data.
