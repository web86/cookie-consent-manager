# Minimal public registry acceptance

Run only against the named disposable local MODX 2.8.8 fixture. Never run the
upgrade harness against production. It uses immutable 1.0.0 and the locally built
1.0.1 review ZIP with the real native Package Manager.

- `projection.php`: native PHP projection, exact technical fields, optional
  stable purpose, no mutation and full internal settings.
- `browser.mjs`: genuine stored consent from 1.0.0, native upgrade in the same
  browser, byte-identical raw consent/fingerprints/ID and permitted mock SDK/map
  requests without another banner; settings, audit configuration and log hashes
  retained by upgrade. Strict minimal/legacy validation; scoped callback and
  controlled ClientID example; RU/EN/TR PHP HTML, cold/warm and no JavaScript.
- Existing sequential provider matrix, Manager, SSR, iframe/JS maps, callback,
  ClientID, Viewer and HTTP receiver suites remain necessary.

The test restarts disposable PHP before native installation because development
builds reuse a signature/resolver path. This prevents stale OPcache hashes from
mixing two local builds; it is not package lifecycle infrastructure. Real vendor
delivery/client hosting and CDN deployment are not asserted by these tests.
